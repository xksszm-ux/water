# Robot V1 硬件实施总计划

## 1. 目标和边界

当前目标是先完成一台基于 STM32F103C8T6、4个普通TT减速电机的可运行V1机器人。

- V1使用左右两路开环PWM，不接编码器，不做RPM和PID。
- ESP32 的 UART2 与 BLE Step 10A 已恢复并完成安全通信验证：仅允许 STOP、状态读取和通知；LVGL、WiFi、OTA仍暂停。
- 在电源、TB6612和电机验收完成前，ESP32不得开放任何非零运动命令。
- PA8舵机只有CubeMX资源，尚无驱动，暂不接。
- CAN属于扩展接口，放在机器人核心功能稳定之后。
- 每一级必须单独通过后才能增加下一级；禁止一次接完再排错。

## 2. 总体优先级

| 顺序 | 阶段 | 目的 | 通过前禁止 |
|---:|---|---|---|
| 0 | 工具与断电检查 | 排除短路、极性和面包板断轨 | 禁止外部上电 |
| 1 | 电源三支路 | 建立4.5 V、3.3 V、可选5 V和公共地 | 禁止接STM32和电机 |
| 2 | STM32最小系统 | 确认供电、下载和FreeRTOS启动 | 禁止接功率负载 |
| 2A | ESP32安全通信 | USB独立供电下验证BLE、UART、STOP和零PWM状态 | 禁止接电机、禁止非零运动 |
| 3 | 电池ADC与PVD | 先建立电机安全门 | 禁止接电机 |
| 4 | OLED与MPU6050 | 建立显示和姿态数据链 | 只接低功耗外设 |
| 5 | W25Q64 | 验证SPI存储 | 禁止边写Flash边改线 |
| 6 | HC-SR04 | 验证安全电平和测距 | Echo未测量前禁止接PA15 |
| 7 | TB6612逻辑与VM | 验证待机、方向和PWM资源 | 电机仍断开 |
| 8 | 四电机分级测试 | 单电机、同侧并联、四轮依次放开 | 轮子先保持悬空 |
| 9 | 整机抗干扰 | 检查压降、复位、传感器和线束 | 未通过不得落地高速运行 |
| 10 | CAN扩展 | 接入SN65HVD230和第二节点 | 单节点不能当正常总线验收 |

## 3. 推荐电源结构

```text
4.5 V电源正极
   |
   +-- 保险/总开关 -- 粗线 ----------------> TB6612 VM / 四个电机
   |
   +-- 3.3 V稳压 --------------------------> STM32、TB6612 VCC、OLED、MPU6050、W25Q64
   |
   +-- 5 V升压（仅在使用标准HC-SR04时） ---> HC-SR04 VCC

4.5 V电源负极
   +-- 星形公共地 --------------------------> 全部模块GND
```

关键结论：

- 电机大电流不能经过面包板长电源轨或细杜邦线；VM和电机输出使用短、较粗导线或端子排。
- 面包板只承担逻辑和传感器连接。
- 4.5 V正极、3.3 V正极和5 V正极是三条不同电源轨，不能互相短接。
- 三条电源的GND必须在电源入口附近星形共地。
- 当前AMS1117-3.3从4.5 V输入只有约1.2 V名义裕量。它可用于无电机的低负载调试，但带四电机前必须证明3.3 V轨在启动和换向时仍稳定。
- 更可靠的整车方案是使用低压差、足够电流的3.3 V稳压方案；未来接ESP32时必须重新核算峰值电流，不能默认继续共用当前AMS模块。

## 4. 分阶段实施

### 阶段0：工具和断电检查

准备：万用表、限流电源或带保险的4.5 V电源、绝缘支架、10 kΩ/15 kΩ/10 kΩ电阻、100 nF电容、VM大电容。

断电完成：

1. 给面包板电源轨贴标签：`4.5V`、`3.3V`、`5V_HC`、`GND`。
2. 检查面包板红蓝长轨是否在中间断开；需要连续的位置用跳线明确桥接。
3. 用蜂鸣档确认所有GND导通。
4. 确认不同正电源轨之间不导通，正极与GND不是近似短路。
5. 暂时断开STM32、TB6612、电机、HC-SR04和ESP32。

通过标准：极性明确、公共地连续、不同正极互不短接。

### 阶段1：只验证电源

1. 只接4.5 V输入和AMS模块，不接其他模块。
2. 黑表笔固定公共GND，依次测AMS输入、AMS输出和各条电源轨。
3. AMS输出应接近3.3 V，且模块不异常发热。
4. 若使用标准HC-SR04，再单独验证5 V升压输出；当前4.5 V原始轨不能假装成稳定5 V。
5. 断电后再进行下一阶段。

失败动作：任何极性错误、3.3 V明显异常或发热，立即断电，禁止接STM32。

### 阶段2：STM32最小系统

只连接：

```text
3.3 V轨 -> STM32任一3.3 V引脚
公共GND -> STM32 GND
ST-Link SWDIO -> PA13
ST-Link SWCLK -> PA14
ST-Link GND   -> 公共GND
```

- Blue Pill两侧的3.3 V引脚属于同一板内电源网络；不需要分别接不同电源。
- AMS VOUT先接3.3 V公共轨，再由公共轨接STM32；不要把两个3.3 V引脚接到两个不同来源。
- 外部3.3 V供电时，避免再由ST-Link或USB向同一电源轨反向供电。
- 烧录Release固件，确认能够下载、启动且没有循环复位或异常发热。

通过标准：两个板载3.3 V测点电压一致，程序稳定运行，故障锁存未异常触发。

### 阶段2A：ESP32安全通信，电机必须断开

本阶段允许ESP32通过USB独立供电；不要把ESP32接到当前AMS1117的3.3 V输出。STM32与ESP32必须公共地。

```text
ESP32 GPIO17 / UART2 TX  -> STM32 PA10 / USART1 RX
ESP32 GPIO16 / UART2 RX  <- STM32 PA9  / USART1 TX
ESP32 GND                -> STM32 GND
```

执行顺序：

1. STM32和ESP32均已启动，四个电机和TB6612电机输出保持断开。
2. 确认ESP32 UART2只使用GPIO16/17；不要占用GPIO1/3的CH340下载日志口。
3. 用手机扫描`SmartRobot-V1`，在运行时长按ESP32 BOOT约3秒打开60秒首次配对/换绑窗口。
4. 配对后读取BLE Status并订阅通知；确认状态显示UART ONLINE、STATUS fresh、左右PWM均为0。
5. 发送BLE STOP测试向量，确认STM32仍返回左右PWM=0。
6. 手机断连后，确认ESP32重新发起STOP握手并恢复广播。

当前已通过：BLE扫描、配对、加密读取、状态通知和STOP写入；仍待完成断连停车、重连恢复、坏帧拒绝和换绑窗口实测。

通过标准：全程左右PWM=0；ESP32和STM32都不复位；UART状态保持ONLINE/FRESH或断线后自动恢复安全STOP。未通过不得进入TB6612和电机阶段。

### 阶段3：先完成电池ADC和安全链

```text
4.5 V正极 -- R1 10 kΩ --+-- PA0
                          |
                        R2 10 kΩ
                          |
公共GND ------------------+

PA0 -- 100 nF -- GND（建议，靠近STM32）
```

1. 先不接PA0，单独测分压中点，应接近输入电压的一半；4.5 V时约2.25 V。
2. 确认中点低于3.3 V后，断电接入PA0。
3. 上电观察`battery_valid`、`battery_mv`、ADC错误位和PVD锁存。
4. 详细标准按`STEP7_HARDWARE_CHECKLIST.md`执行。

通过标准：显示电压接近万用表，电池状态有效，无ADC/PVD错误。未通过不得接电机。

### 阶段4：先OLED，后MPU6050

共用I2C1：

```text
PB6 -> OLED SCL + MPU6050 SCL
PB7 -> OLED SDA + MPU6050 SDA
3.3 V -> 两模块VCC
GND -> 两模块GND
```

执行顺序：

1. 先只接OLED，确认地址和稳定显示。
2. 断电后再并接MPU6050，确认姿态有效位和显示更新。
3. SDA/SCL上拉只能接3.3 V；整条总线只需要一组有效上拉。
4. 如果两个模块都自带上拉，必须核算并联后的等效阻值，不能继续盲目增加外部上拉。

通过标准：OLED不花屏，MPU数据持续更新，I2C错误不增长。

### 阶段5：W25Q64

```text
PB12 -> CS
PB13 -> SCK
PB14 <- MISO
PB15 -> MOSI
3.3 V -> VCC
GND -> GND
```

- W25Q64只能使用3.3 V。
- VCC旁放100 nF去耦，CS上电必须保持高电平。
- 先验证JEDEC ID，再验证擦除、写入、读回和掉电重启扫描。

通过标准：ID正确、写后读回和CRC通过、无Flash错误位。

### 阶段6：HC-SR04

标准HC-SR04按稳定5 V模块处理：

```text
5 V_HC -> VCC
GND -> 公共GND
PB5 -> TRIG

ECHO -- 10 kΩ --+-- PA15
                  |
                 15 kΩ
                  |
                 GND
```

1. 先不给PA15接线，测模块VCC。
2. 暂不接HC-SR04 Echo和PA15：把稳定5 V临时加到10 kΩ上端，静态测分压中点应约3.0 V且不得超过3.3 V；测完断电并移除临时5 V。
3. 把HC-SR04 Echo接到10 kΩ上端，确认电阻位置无误后，断电把分压中点接PA15。
4. 用10 cm、50 cm、100 cm平面目标逐点测试；万用表不能准确捕获短Echo脉冲，脉宽和峰值应使用示波器或逻辑分析仪确认。
5. 详细标准按`STEP6A_HCSR04_CHECKLIST.md`执行。

通过标准：距离有效、误差合格、拔掉Echo后有效位在200 ms内清除、无中断风暴。

### 阶段7：TB6612逻辑和电机电源，仍不接电机

```text
3.3 V -> TB6612 VCC
4.5 V -> TB6612 VM
公共GND -> TB6612全部GND

PA4 -> STBY
PA6 -> PWMA       PB8 -> AIN1    PB9  -> AIN2
PA7 -> PWMB       PB10 -> BIN1   PB11 -> BIN2
```

1. 先只接VCC、GND和控制脚，VM保持断开；确认上电PA4/STBY为低。
2. 检查模块是否自带STBY上拉或焊桥；不能把STBY永久硬接3.3 V。建议PA4侧保留约10 kΩ下拉，确保复位期间待机。
3. 再断电接入4.5 V VM，电机输出仍保持空载。
4. VCC附近放100 nF；VM附近放100 nF陶瓷和约220～470 uF电解电容。
5. 确认TB6612全部GND脚都接公共地。

通过标准：待机时STBY约0 V，PWM为0，无异常发热，STM32不复位。

### 阶段8：电机分级接入

1. 托起底盘，确保四轮完全悬空。
2. 先每侧各接1个电机，运行一次10% PWM测试。
3. 验证左、右、正转、反转、停止和300 ms超时停车。
4. 断电后把同侧第二个电机并联到同一通道；确认两个轮子在底盘意义上推动同一方向。
5. 每个电机端子并联约100 nF陶瓷电容，电机线成对绞合并远离I2C、PA0和Echo线。
6. 两个电机并联后的启动和堵转电流会相加；必须核对电机堵转电流与TB6612单通道能力。禁止主动堵转测试。
7. 测试完必须把`MOTOR_STEP4_TEST_ENABLED`恢复为0。

通过标准：方向正确、可靠停车、换向不复位、TB6612和稳压模块不过热。

### 阶段9：整机抗干扰和落地测试

1. 先保持轮子悬空，同时运行OLED、MPU6050、Flash、超声波和四电机。
2. 观察3.3 V轨、电池状态、PVD锁存、任务栈高水位、I2C/SPI/超声波错误。
3. 重点测试电机启动、急停和正反换向时是否复位或丢失传感器。
4. 通过后放到地面，先用低PWM、短距离测试前进、后退、左右转和STOP。
5. 最后再连续运行10分钟，检查温升、线束松动和电源压降。

硬门槛：任何复位、PVD锁存、3.3 V掉压、TB6612过热或传感器持续失效，都必须退回电源/布线阶段，不允许通过提高PWM掩盖问题。

### 阶段10：CAN扩展，最后接

```text
PA12 -> SN65HVD230 TXD
PA11 <- SN65HVD230 RXD
3.3 V -> VCC
GND -> 公共GND
RS -> GND
CANH/CANL -> 双绞总线
```

- 只允许3.3 V供电。
- 总线两个物理末端各一个120 Ω，中间节点不加终端。
- 必须至少有第二个正常CAN节点提供ACK；单节点正常模式报错是预期现象。
- 详细按`STEP8_CAN_CHECKLIST.md`执行。

## 5. 当前明确不接或不开放的接口

- ESP32 UART：PA9/PA10已接入ESP32 GPIO17/16，仅用于Step 10A STOP/状态通信；电机验收前禁止发送任何非零运动命令。
- 舵机：PA8/TIM1_CH1已占资源，但驱动尚未实现。
- 编码器：PA1、PA5、PB3、PB4仅预留，普通电机V1不接。
- 不要因为引脚已经配置就宣称相应硬件功能已完成。

## 6. 总验收结论规则

只有同时满足以下条件，才能宣称V1硬件完成：

- 电源轨和ADC已用万用表验收。
- 四电机悬空和落地低速测试均通过。
- 电机启动/换向时STM32不复位，3.3 V轨稳定，无PVD故障。
- ESP32与STM32的断连、STOP和状态链在电机断开及接入后均保持安全；BLE连接本身不能绕过STM32安全门。
- OLED、MPU6050、W25Q64和HC-SR04在电机运行时仍稳定。
- STOP、命令超时、低压和致命Fault都能可靠停车。
- 连续运行10分钟无异常发热、线束松动、中断风暴或任务栈风险。

在此之前，只能分别声明“软件构建通过”或“某一级硬件通过”，不能声明整机完成。
